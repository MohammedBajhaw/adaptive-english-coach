# Adaptive English Coach

نظام تعلم إنجليزية شخصي لمهندس ميكاترونيك حديث التخرج. يركز على الإنجليزية العملية والهندسية، ويجمع بين المفردات والقواعد والاستماع والمحادثة والكتابة مع تتبع أدلة التعلم وتقدير مستوى ديناميكي.

## الروابط

- **المستودع:** https://github.com/MohammedBajhaw/adaptive-english-coach
- **النشر الحالي على GitHub Pages:** https://mohammedbajhaw.github.io/adaptive-english-coach/
- **مشروع Supabase:** يستخدمه التطبيق لتسجيل الدخول وتخزين تقدم المتعلم. لا تضع مفاتيح Supabase السرية في المستودع.

## ما الذي يقدمه النظام؟

- واجهة عربية متجاوبة للهاتف واللابتوب، مع بقاء المحتوى التعليمي باللغة الإنجليزية وترجمة عربية مساعدة.
- تسجيل دخول بالبريد الإلكتروني عبر Supabase Magic Link، مع حفظ الجلسة تلقائيًا.
- تشخيص أولي يبدأ من نطاق A2/B1 ولا يثبت مستوى المتعلم نهائيًا.
- معايرة تدريجية تبني تقديرًا عمليًا من المحاولات والنتائج والتقييمات الفعلية.
- خمس مهارات يومية: **Vocabulary, Grammar, Listening, Speaking, Writing**.
- محتوى هندسي مرتبط بالميكاترونيك، مثل الحساسات، المحركات، المتحكمات، المشغلات، الاختبار واستكشاف الأعطال.
- ثلاث طرائق تعلم:
  - `steady`: جلسة خفيفة.
  - `balanced`: جلسة متوازنة.
  - `intensive`: جلسة مكثفة.
- أوزان قابلة للتعديل للمهارات الخمس، مع إبقاء المهارات كلها في الخطة اليومية وتغيير عمق النشاط.
- بطاقات مفردات مع معنى عربي، نطق IPA، أمثلة مترجمة، ومراجعة متباعدة.
- قواعد بشرح عربي، أسئلة اختيار من متعدد، وسؤال كتابي للمراجعة الذاتية.
- محادثة يومية بموضوع وبرومبت وكلمات مستهدفة وترجمة، مع تسجيل تقييم من 10.
- استماع يومي بمصدر وأسئلة فهم قصيرة.
- كتابة مهنية قصيرة، مع مراجعة ذاتية أو تصحيح ذكي اختياري عند تجهيز مزود خارجي.
- تقارير يومية وأسبوعية وشهرية لكل مهارة.
- سجل محتوى يمنع التكرار غير المقصود ويعرف ما تم تقديمه أو إكماله أو إتقانه.
- تذكيرات داخلية للمتعلم، مع منطق منع التكرار في اليوم نفسه.

## التقنية والبنية

```text
React 19 + TypeScript + Vite
Tailwind CSS 4 + مكونات Radix/shadcn-style
Wouter للتنقل
Supabase Auth + PostgreSQL + Row Level Security
GitHub Pages للاستضافة الثابتة
GitHub Actions للبناء والنشر
Vitest للاختبارات
```

التطبيق المنشور على GitHub Pages هو **واجهة ثابتة**. لذلك يتصل المتصفح مباشرة بـ Supabase باستخدام المفتاح العام publishable/anon، بينما تحمي Supabase البيانات بسياسات RLS. لا توجد حاجة إلى خادم Manus لتشغيل النشر الثابت.

يوجد في المشروع أيضًا مجلد `server/` يحتوي على منطق واختبارات وخيارات تكامل أقدم أو قابلة لإعادة الاستخدام. عند التشغيل المستقل على GitHub Pages استخدم `build:pages`، ولا تعتمد على خادم Manus في الإنتاج.

## صفحات التطبيق وما المطلوب من كل قسم

| المسار | القسم | الاستخدام المقصود |
|---|---|---|
| `/` | لوحة اليوم | نقطة البداية: المهام اليومية، نسبة الإنجاز، الفجوات، البطاقات المستحقة والتنبيهات |
| `/diagnostic` | التشخيص | قياس أولي للقواعد والمفردات والكتابة والثقة في الكلام؛ النتيجة نقطة بداية وليست حكمًا نهائيًا |
| `/cards` | البطاقات | مراجعة الكلمات المستحقة، ثم تقييمها بـ Again/Hard/Good/Easy؛ إكمال البطاقات ينعكس تلقائيًا على مهمة المفردات |
| `/grammar` | القواعد | قراءة شرح عربي للقاعدة، الاطلاع على مصادرها، حل الأسئلة، ثم كتابة مثالين أو إجابة كتابية |
| `/conversation` | المحادثة | قراءة الموضوع والكلمات وترجمتها، نسخ البرومبت إلى أداة محادثة، إجراء الحوار، ثم حفظ التقييم من 10 |
| `/listening` | الاستماع | فتح المصدر، الاستماع بتركيز، الإجابة عن أسئلة الفهم، وحفظ النتيجة كدليل استماع |
| `/writing` | الكتابة | تنفيذ مهمة كتابة مهنية قصيرة، مراجعتها ذاتيًا أو إرسالها للتصحيح الذكي عند توفر مزود خارجي |
| `/reports` | التقارير | مراجعة التقارير اليومية والأسبوعية والشهرية لكل مهارة بدل الاعتماد على عداد عام فقط |
| `/settings` | الإعدادات | ضبط التخصص، الأهداف، النمط، الوقت اليومي، أوزان المهارات والتذكيرات |

## كيف يعمل تدفق الاستخدام؟

1. يفتح المتعلم الموقع ويسجل الدخول عبر Magic Link.
2. ينشئ التطبيق ملفًا في `learner_profiles` عند أول دخول إن لم يكن موجودًا.
3. عند فتح لوحة اليوم، تنشأ خمس مهام يومية مرتبطة بالتاريخ ومعرفات المحتوى المحلي.
4. يسجل التطبيق أن المحتوى ظهر للمتعلم في `learner_content_progress`.
5. ينفذ المتعلم أنشطة المهارات، وتحفظ النتائج أو الأدلة في `diagnostic_attempts` أو الجداول المختصة.
6. عند إكمال نشاط، تتحدث حالة `daily_tasks` إلى `completed` ويزداد سجل إكمال المحتوى.
7. عند مراجعة بطاقة، يحدث موعد المراجعة وقوة الحفظ ويسجل الحدث في `card_reviews`.
8. يحسب النظام اللقطات والتقارير من البيانات المحفوظة، ولا يعتمد على بيانات تجريبية ثابتة.
9. يستخدم المستوى العملي الأدلة المتراكمة لعرض تقدير A2/B1 قابل للتغير مع الوقت.

## أنماط التعلم والوقت والأوزان

- **Steady / هادئ:** عدد أقل من الكلمات والأسئلة، محادثة واستماع أقصر، مناسب لبناء عادة يومية.
- **Balanced / متوازن:** ناتج متوسط لكل المهارات، وهو الاختيار الافتراضي المناسب لمعظم الأيام.
- **Intensive / مكثف:** كلمات أكثر، أسئلة أكثر، ووقت أطول للمحادثة والاستماع والكتابة.

تُقرأ هذه القيم من `client/src/lib/studyMode.ts` في صفحات البطاقات والقواعد والاستماع والمحادثة والكتابة حسب `study_mode` المحفوظ في `learner_profiles`.

الوقت اليومي يحدد سعة الخطة، بينما الأوزان تحدد أين يزداد العمق. لا يؤدي رفع وزن المحادثة إلى حذف القواعد أو الاستماع؛ بل يعطي المحادثة نشاطًا أعمق أو أسئلة/إنتاجًا أكبر ضمن الوقت المتاح.

## Supabase: الإنشاء والإعداد

1. أنشئ مشروعًا مجانيًا جديدًا في Supabase.
2. افتح **SQL Editor** ونفذ الملف:

   ```text
   supabase/migrations/001_initial_learning_schema.sql
   ```

3. من **Authentication > URL Configuration** أضف:
   - Site URL: `https://mohammedbajhaw.github.io/adaptive-english-coach/`
   - Redirect URL: `https://mohammedbajhaw.github.io/adaptive-english-coach/`
   - وأضف رابط التطوير المحلي عند الحاجة.
4. لا تعطل RLS ولا تستخدم `service_role` داخل الواجهة.
5. استخدم رابط المشروع والمفتاح العام فقط في متغيرات Vite.

### الجداول الأساسية

- `learner_profiles`: تفضيلات المتعلم والنمط والأوزان والتخصص.
- `skill_snapshots`: لقطات المستوى العملي لكل تاريخ.
- `diagnostic_attempts`: محاولات وأدلة المهارات.
- `vocabulary_cards`: البطاقات ومواعيد المراجعة وقوة الحفظ.
- `card_reviews`: سجل كل مراجعة بطاقة.
- `daily_tasks`: مهام اليوم وحالاتها.
- `learner_content_progress`: سجل تقديم وإكمال وإتقان المحتوى.
- `learner_notifications`: التذكيرات الداخلية.

كل جدول محمي بسياسة تمنح المستخدم المصادق عليه الوصول إلى صفوفه فقط باستخدام `auth.uid() = user_id`.

## التشغيل محليًا

المتطلبات: Node.js 22 أو أحدث و`pnpm`.

```bash
git clone https://github.com/MohammedBajhaw/adaptive-english-coach.git
cd adaptive-english-coach
pnpm install --frozen-lockfile
cp .env.github-pages.example .env.local
```

عدّل `.env.local`:

```env
VITE_SUPABASE_URL=https://YOUR_PROJECT.supabase.co
VITE_SUPABASE_PUBLISHABLE_KEY=YOUR_PUBLIC_KEY
```

تشغيل واجهة GitHub Pages محليًا:

```bash
pnpm dev:pages
```

فحص TypeScript واختبارات الوحدة والتكامل المحلية:

```bash
pnpm check
pnpm test
```

بناء نسخة الإنتاج الثابتة ومعاينتها:

```bash
pnpm build:pages
pnpm preview:pages
```

الناتج يكون في `dist/github-pages/`. لا ترفع `.env.local` أو أي مفتاح سري إلى Git.

## النشر إلى GitHub Pages

ملف `.github/workflows/deploy-pages.yml` ينفذ تلقائيًا عند كل push إلى `main`:

1. يثبت Node 22 وpnpm.
2. يثبت الاعتمادات من lockfile.
3. يشغل `pnpm build:pages`.
4. يمرر `VITE_SUPABASE_URL` و`VITE_SUPABASE_PUBLISHABLE_KEY` من GitHub Secrets.
5. ينسخ `index.html` إلى `404.html` لدعم التنقل داخل SPA.
6. ينشر مجلد `dist/github-pages` عبر GitHub Pages.

في إعدادات المستودع، أضف الأسرار التالية في **Settings > Secrets and variables > Actions**:

```text
VITE_SUPABASE_URL
VITE_SUPABASE_PUBLISHABLE_KEY
```

ثم من **Settings > Pages** اختر **GitHub Actions** كمصدر النشر. إعداد `base` يتعرف تلقائيًا على اسم المستودع من `GITHUB_REPOSITORY`، لذلك يعمل المسار `/adaptive-english-coach/` على GitHub Pages.

## المحتوى وكيفية إضافة دروس جديدة

المحتوى لا يولده API خارجي أثناء الاستخدام. هذا مقصود حتى يبقى المحتوى ثابتًا، عالي الجودة، ومناسبًا للميكاترونيك حتى عند استخدام مزود AI مجاني لاحقًا.

- أضف ملفات الدروس في `server/content-library/weeks/week-XX/`.
- حافظ على معرف ثابت وفريد لكل درس وتمرين ومصدر.
- حدّث مستوردات `client/src/lib/localLessons.ts` عند إضافة أسبوع جديد.
- لا تعِد استخدام معرف درس قديم لمحتوى جديد؛ سجل التقدم يعتمد على المعرف لمنع التكرار.
- استخدم الملفات البحثية وقوالب التوليد الموجودة في جذر المشروع كمرجع قبل توليد محتوى جديد.
- راجع الروابط والأسئلة والمعرفات قبل الدمج، ثم شغل الاختبارات.

ملاحظة: الحزمة الحالية 28 يومًا (4 أسابيع × 7). بعد اليوم 28 يعود الاختيار اليومي إلى بداية الحزمة، لذا أضف أسابيع جديدة قبل انتهاء الدورة. المفردات الـ28 تُضاف إلى بطاقات المتعلم تدريجيًا (5 أو 7 أو 10 كلمات جديدة يوميًا حسب النمط) ثم تبقى في المراجعة المتباعدة.

## تصحيح الكتابة بالذكاء الاصطناعي

الوضع الأساسي مستقل ولا يحتاج AI: يطبق المتعلم مراجعة ذاتية موجهة. يوجد تكامل اختياري لمزود خارجي متوافق مع OpenAI موضح في [AI_PROVIDER_SETUP.md](./AI_PROVIDER_SETUP.md).

التصحيح الذكي يعمل عبر دالة Supabase Edge Function في `supabase/functions/correct-writing/`، فلا يصل مفتاح المزود إلى المتصفح. لتفعيله:

```bash
supabase login
supabase link --project-ref doygchyxxbgbcbztwckh
supabase secrets set AI_CORRECTION_BASE_URL=https://provider.example/v1 AI_CORRECTION_API_KEY=... AI_CORRECTION_MODEL=model-id
supabase functions deploy correct-writing
```

قبل نشر الدالة أو عند غياب الأسرار، تعرض صفحتا القواعد والكتابة مراجعة ذاتية موجهة. في القواعد تُحسب النتيجة من أسئلة الاختيار فقط، وفي الكتابة من تقييم المتعلم لنصه من 10. لا تُمنح أي علامة افتراضية.

## الاختبارات والتحقق

الاختبارات تغطي محرك التعلم، اختيار المحتوى، التقارير، البطاقات، التذكيرات، المسارات، وتكاملات Supabase المتاحة محليًا. قبل أي push:

```bash
pnpm check
pnpm test
pnpm build:pages
```

وتحقق يدويًا من:

- تسجيل الدخول والرابط السحري وحفظ الجلسة.
- إنشاء مهام اليوم بعد أول دخول.
- إكمال البطاقات وانعكاسها على لوحة اليوم.
- حفظ تقييم المحادثة.
- حفظ نتيجة القواعد والاستماع والكتابة.
- ظهور التقرير الأسبوعي والشهري.
- عمل الموقع على الهاتف وعلى مسار GitHub Pages الفرعي.

## الوضع الحالي والعناصر المتبقية

المشروع في حالة نقل مستقلة عملية: GitHub Pages + Supabase + محتوى محلي، مع إصلاح إنشاء مهام اليوم وربط المحاولات السابقة بالمهمة الصحيحة.

العناصر التي تستحق المراجعة التالية موجودة أيضًا في `todo.md`، وأهمها:

- تحقق بصري نهائي لخطة اليوم في الأنماط الثلاثة على الهاتف واللابتوب.
- مراجعة جودة حزمة المحتوى الحالية قبل إضافة أسابيع جديدة.
- نشر دالة `correct-writing` وضبط أسرار المزود لتفعيل التصحيح الذكي.
- إضافة أسابيع محتوى جديدة بعد الأسبوع الرابع.
- اختبار نهائي كامل من تسجيل الدخول إلى إكمال مهمة ثم ظهورها في التقرير.

## قواعد أمان مهمة

- لا ترفع `.env` أو مفاتيح AI أو `service_role` إلى GitHub.
- مفتاح Supabase العام مخصص للمتصفح، لكن الأمان الحقيقي يأتي من RLS؛ راجع السياسات عند تعديل المخطط.
- لا تستدعِ مزود AI السري مباشرة من React.
- استخدم migrations قابلة للتتبع بدل تعديل جداول الإنتاج يدويًا دون ملف SQL.
- بعد أي تعديل على المخطط أو منطق التعلم شغل `pnpm check` و`pnpm test` و`pnpm build:pages`.
